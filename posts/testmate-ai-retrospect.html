在AI时代，使用Vibe Coding的代码，HR怎么看？

2026-09-22 · CodeCat

说实话，我并不清楚HR的真实看法，但对我个人而言，我认为在AI时代我们比起Coding能力，更应该注重Debug能力。

老板不在乎谁敲的键盘，只在乎你懂不懂这些代码。所以我写了这篇博客，比起给别人看，更多的是让自己接受Vibe Coding

我用AI写的项目是什么

TestMateAI，这个项目是我和AI共同完成的，是用来生成测试用例的（PS：手写测试用例太麻烦，豆包生成的有时候比较抽象不好复制。）

所以我写好PRD、提示词和系统设计，然后让AI在我搭建好的框架下填充。最后效果就是：输入一段需求文字，AI 帮你生成功能测试用例，还能导出 Excel。

比如你输入"用户登录功能，支持账号密码登录"，它会输出 10 条测试用例——正常登录、密码错误、账号为空、SQL 注入……覆盖正常和异常场景。

讲几个我觉得值得说的点

1. DeepSeek 怎么接的

核心就改了一个地方——base_url：

llm = ChatOpenAI(
    api_key=DEEPSEEK_API_KEY, # 其实还有这里（换上自己的KEY别上传<可以用.ignore 忽略本地写KEY的文件>）
    base_url="https://api.deepseek.com",  # 就改这里
    model="deepseek-chat",
    temperature=0.3
)

DeepSeek 兼容 OpenAI 的 API 格式，所以 LangChain 的 ChatOpenAI 不用改任何代码，换个地址就行。温度设 0.3，因为我要的是稳定的 JSON 输出，不是创意写作。

2. AI 返回不是每次都靠谱

这是实际跑起来才发现的问题。AI 有时候会在 JSON 前面加一句"好的，以下是你需要的测试用例："，直接 json.loads() 就炸了。

所以我加了重试：

max_retries = 2
for attempt in range(max_retries):
    try:
        cases = generate_cases(request.requirement)
        return {"code": 200, "data": cases}
    except json.JSONDecodeError:
        # AI 返回了但格式不对
        if attempt < max_retries - 1:
            time.sleep(2)
            continue
        return {"code": 500, "message": "AI返回格式错误"}
    except (ConnectionError, TimeoutError, OSError):
        # 网络炸了
        if attempt < max_retries - 1:
            time.sleep(2)
            continue
        return {"code": 503, "message": "AI服务不可用"}

重试一次不行就告诉用户"服务不可用"。500 是 AI 的锅，503 是网络的锅，状态码要分开。

后来我想了想，其实应该先 try 用正则把 JSON 部分提取出来再 parse，这样成功率会更高。下一步可以优化。

3. 密码存储

注册时密码用 bcrypt 加盐哈希，存的是哈希值不是明文：

hashed = bcrypt.hashpw(
    password.encode('utf-8'),
    bcrypt.gensalt()  # 随机盐
).decode('utf-8')

登录时不是"解密"，是拿用户输入的密码再做一次哈希，比一比结果一不一样。哈希是单向的，反推不了原密码。

然后发一个 JWT token，7 天有效。之后用户每次请求在 Header 里带上 Authorization: Bearer <token>，后端 decode 一下就知道是谁了。

4. 数据隔离

查历史记录的时候始终带 user_id 过滤，用户 A 看不到用户 B 的东西：

records = db.query(CaseRecord)
    .filter(CaseRecord.user_id == current_user.id)
    .order_by(CaseRecord.id.desc())
    .offset(offset)
    .limit(size)
    .all()

有人想访问别人的记录？直接 403 打回去。

5. Excel 导出踩的坑

中文文件名在 HTTP 头里会乱码。HTTP 头只允许 ASCII，中文得用 RFC 5987 编码：

headers={"Content-Disposition": f"attachment; filename*=UTF-8''{quote(filename)}"}

这个坑踩了好久才找到原因……

部署

  • 后端扔在 Render 上，MySQL 做生产数据库
  • 前端扔在 Vercel 上，自动构建
  • CORS 在 FastAPI 里配了 Vercel 的域名
  • API Key、JWT 密钥这些全走环境变量，不硬编码

所以 AI 写了代码，我学到了什么？

老实说大部分代码确实不是我一个字一个字敲的。但写这篇博客的时候，我完全可以靠自己回答这些问题：

  • 为什么用 DeepSeek 不用 OpenAI？—— 便宜，API 兼容
  • 为什么重试 2 次不是 3 次？—— 够了，再多就是浪费时间
  • 为什么用 JWT 不用 Session？—— 前后端分离，无状态方便
  • 为什么用内存流不用临时文件？—— 云上没那么多磁盘给你玩

或者其他项目的问题，我觉得在这个时代，我们应该是利用AI加速自己成长，简单重复的任务直接AI接管，我们可以学更多东西和技术。
